# ARCHITECTURE — Love Game

## Assembly graph (strict DAG, no cycles)

```
LoveGame.Core            (no refs - bootstrap, services, events, save, pooling, materials, Interactable, IWorldQuery)
 ├─ LoveGame.World       (regions, streaming, day/night, weather, water, NPC, wildlife, fast travel)
 ├─ LoveGame.Player      (input abstraction, controller, camera, character rig, partner AI)
 ├─ LoveGame.Inventory   (items, gifts, collectibles, memories)
 ├─ LoveGame.Audio       (synthesized clips + audio service)
 └─ LoveGame.Content     (packs, download manager, Addressables bridge; versionDefines gate)
LoveGame.Interaction     (Core + Player + Inventory)   — interactables scan, couple framework, emotes
LoveGame.Vehicles        (Core + Player + World + Audio)
LoveGame.Activities      (Core + Player + Inventory + Interaction + World + Audio)
LoveGame.Home            (Core + Player + Inventory + Interaction + World)
LoveGame.UI              (Core + World + Player + Interaction + Vehicles + Activities + Home + Inventory + Audio + Content)
LoveGame.Game            (ALL) — WorldSystems, MainMenuBootstrap (scene boots)
LoveGame.EditorTools     (ALL, Editor-only) — setup wizard, CI builder, generators
LoveGame.Tests.EditMode / .PlayMode
```

Editor code is isolated (`includePlatforms: [Editor]`); runtime code never references UnityEditor.

## Runtime flow

```
00_Bootstrap (GameBootstrap, DontDestroyOnLoad)
  → services host + config load → 01_MainMenu
     → MainMenuScreen → new/continue → loads save
        → 02_World (WorldSystems)
           → register ALL services → one InitializeAll pass
           → build player + camera + partner → bind cross-refs → HUD
           → TeleportTo(saved region) → streamer builds region(s)
           → restore time/weather → publish PlayerSpawned
```

Scene-referenced components (only three): `GameBootstrap`, `MainMenuBootstrap`, `WorldSystems`.
Everything else is code-created — UI, services, world content — so scenes stay tiny and merge-safe.

## Key patterns

- **Service locator with per-service idempotent init** — late registrations initialize on the
  next `InitializeAll()` pass; safe across scene reloads.
- **Typed event hub** (`GameEvents`) — systems never call each other for notifications
  (weather→audio, collectibles→UI, region→ambience all flow through events).
- **IWorldQuery interface in Core** — player/vehicle movement asks for heights/water through
  the abstraction; the World assembly implements it (bilinear heightfield lookups). No
  gameplay→world hard coupling.
- **WorldSystemsBridge** — UI assembly reads world state through delegate hooks assigned by
  the game assembly, keeping UI reusable.
- **Data-driven regions** — regions.json (blockout) and RegionDefinition ScriptableObjects
  (production, editor-generated) hydrate the same `RegionData` runtime model.
- **Procedural placeholders behind stable APIs** — PlayerCharacter slots, VehicleConfig,
  FurnitureVisual, MaterialLibrary: final assets replace visuals, not code.
- **Atomic writes everywhere** — saves (tmp+rename+backup), settings, downloaded packs.
- **Distance-based simulation tiers** for NPCs/wildlife (Near/Medium/Far/OutOfRange) and
  cell-grouped props; quality levels scale prop/NPC budgets, render scale, shadows.

## Save system

`SaveData` v1: player, world (time/weather/discoveries), inventory, progress (collectibles/
memories/activities/relationship), home furniture, world vehicles, content packs.
Provider abstraction (`ISaveProvider`) — local today, cloud later. Migrations step forward
one version at a time. Autosave every 2 minutes + on pause/quit.

## Rendering

URP (4 pipeline assets: Low→Ultra, generated by the setup wizard) + pipeline-agnostic custom
shaders (CGPROGRAM-based, render in URP and Built-in as fallback):
`LoveGame/GradientSkybox` (3-band gradient + sun disc + moon + procedural stars),
`TerrainVertexColor` (biome-blended vertex colors + matched exponential fog),
`StylizedWater` (crossing wave trains, fresnel, transparency), `EmissiveUnlit` (bloom-friendly).
Custom shaders take fog from global uniforms (`_LGFogColor/_LGFogDensity/_LGFogStart`) that the
day/night system syncs with `RenderSettings.fog` so standard + custom materials fog identically.
